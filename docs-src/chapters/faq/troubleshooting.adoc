== Troubleshooting

Each entry gives what you see, why it happens, and what to do. They are in the order you will meet them. If yours is not here, press
`Ctrl+Shift+P` in VS Code and run *Workspaces Console: Get Help*, or in Debian run `ws-host context` and `ws-host doctor`, and paste what they print
to a person or an AI. They contain no passwords.

=== WSL is not installed, or Debian says an error starting with 0x8007

*Why:* Windows has WSL turned off, or the computer's virtualization is off.

*Fix:* Open PowerShell as administrator and run `wsl --install --no-distribution`, then restart. If it complains about virtualization, turn
it on in your computer's BIOS or firmware settings; Microsoft's page
https://support.microsoft.com/en-us/windows/enable-virtualization-on-windows-c5578302-6e43-4b4b-a449-8ced115f58e1[Enable virtualization on
Windows] shows how. More: https://learn.microsoft.com/en-us/windows/wsl/troubleshooting[Troubleshooting WSL].

=== The Debian window opens and closes at once, or never gets to a prompt

*Why:* The first-time setup did not finish, or WSL needs updating.

*Fix:* In PowerShell run `wsl --update`, then `wsl --shutdown`, and open Debian again. If it still fails, run `wsl --unregister Debian` and
install Debian again from the Store; this erases only the Debian you just made.

=== I do not remember my password

*Why:* The password you made in the Debian window is what `sudo` asks for, and Windows does not know it.

*Fix:* In PowerShell run `wsl -d Debian -u root`, then `passwd YOURNAME` (your Debian username), type the new password twice, and type `exit`.

=== `curl: command not found`, `wget: command not found`, or `git: command not found`

*Why:* A fresh Debian is small. It has none of them, and VS Code needs `wget` to set itself up inside Debian.

*Fix:* `cd && sudo apt update && sudo apt install -y curl wget git`. The `cd` first takes you to your Linux home. The installer also installs what it needs by itself, after telling you.

=== The installer says it cannot reach the network, or shows a certificate error

*Why:* Your network blocks the download, you work behind a company proxy, or Debian's clock is wrong.

*Fix:* Open a web browser on Windows and check that https://github.com loads. On a company network, ask your IT team for the proxy address
and set it in Debian: `export https_proxy=http://PROXY:PORT` and run the installer again. A certificate error also appears when the
clock is off; see the entry on the clock below.

=== `sudo` says you are not in the sudoers file

*Why:* You are using an account that cannot install things.

*Fix:* Use the account you made when Debian first opened; it can. Or in PowerShell run `wsl -d Debian -u root`, then `usermod -aG sudo
YOURNAME`, `exit`, and open Debian again.

=== `ws-host: command not found`

*Why:* The terminal you are in started before the installer finished, so it does not know the new folder `~/.local/bin`.

*Fix:* The installer ends by showing the line to type, `exec bash -l`, which starts a fresh login shell that finds it. You can also close the
Debian window and open it again. If it still fails, run `ws-host shell add bash`, which also puts `~/.local/bin` on your `PATH`, or run
`echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc` and open a new window.

=== "Setting up VS Code" takes a long time

*Why:* The first time, VS Code downloads a small helper into Debian (about 100 MB) before it can install anything. It says nothing while it does,
and on a slow network that takes minutes.

*Fix:* Wait. The line at the bottom shows a spinner and, as the helper arrives, how many megabytes have come, for example
`⠴ Setting up VS Code inside Debian (the first time downloads its helper) 42 MB downloaded (95s)`. If it gives up after fifteen minutes it
says so, nothing is lost, and running `ws-host workspace ensure` again carries on from where it got to.

=== The installer seems stuck on a slow network

*Why:* Downloads over a slow connection take minutes, and the installer keeps its output quiet so the screen stays calm.

*Fix:* Look at the line at the bottom of the window. A spinner with a number of seconds, such as `⠴ Installing uv (42s)`, means it is working,
and a download shows how much has come. Wait for the tick. If it stops with a cross, the lines under it say why, and running the same
installer again is safe and carries on where it left off.

=== The sign-in code does not work, or the browser does not open

*Why:* The code lasts a few minutes, and Debian cannot open Windows' browser by itself.

*Fix:* Run `ws-host auth new github` again for a new code. Copy the address it prints into your browser on Windows by hand. Make sure you are
signed in to the right GitHub account in that browser.

=== The browser says the code is wrong or expired, or sign-in fails, after a long wait

*Why:* The clock in Debian can be far off after the computer sleeps, which makes secure connections and codes fail.

*Fix:* In PowerShell run `wsl --shutdown`, open Debian again, and try once more. If the clock is still wrong, in Debian run
`sudo hwclock -s`.

=== "could not read Username", or a repository did not copy

*Why:* You are not signed in to GitHub, or your account cannot see that repository.

*Fix:* Run `ws-host auth status`. If it says you are not signed in, run `ws-host auth new github` (see <<sign-in>>) and then `ws-host workspace
ensure`. If you are signed in, ask the repository's owner to give your GitHub account access.

=== `code: command not found` in Debian

*Why:* VS Code is not installed on Windows, or its *Add to PATH* option was off, or Debian was open before you installed it.

*Fix:* Install VS Code on Windows from https://code.visualstudio.com/[code.visualstudio.com]. Close the Debian window, open it again, and
type `code --version`. If it still fails, open VS Code on Windows, press `Ctrl+Shift+P`, run *Shell Command: Install 'code' command in PATH*,
and try again.

=== VS Code opens on Windows, not inside Debian

*Why:* You started it from the Start menu, or the WSL extension is missing. The bottom-left corner does not say *WSL: Debian*.

*Fix:* Install the *WSL* extension from Microsoft (see <<vscode>>). Then in the Debian window go to your repository and run `code .`. Or
in VS Code press `Ctrl+Shift+P` and run *WSL: Open Folder in WSL*.

=== The Workspaces Console does not show up

*Why:* VS Code has not reloaded since `ws-host vscode ensure`, or you ran it before VS Code had opened a folder in Debian once, or there was no release of it to install yet.

*Fix:* Open a folder with `code .` from Debian, then run `ws-host vscode ensure` again, then in VS Code press `Ctrl+Shift+P` and run *Developer:
Reload Window*. Check *Extensions*, search `@installed`, and look for *Workspaces Console*.

=== `ws-host vscode ensure` says it could not install the Workspaces Console

*Why:* There is no release of the Workspaces Console with a fingerprint `ws-host` can check yet, or GitHub could not be reached, or the file that arrived did not
match its fingerprint. In each case `ws-host` installs nothing rather than something it cannot vouch for.

*Fix:* Check the network (see the entry on the network above), then run `ws-host vscode ensure` again. If it says the file did not match, wait and try again later,
and tell whoever looks after `ws-host`: a file that does not match should never be installed by hand.

=== VS Code says Restricted Mode, and nothing in the Workspaces Console works

*Why:* VS Code does not trust the folder yet. The Workspaces Console refuses to run anything in Restricted Mode, on purpose.

*Fix:* Press *Manage* in the banner, then *Trust*. See https://code.visualstudio.com/docs/editor/workspace-trust[Workspace Trust].

=== `ws-host vscode ensure` says it left my settings alone

*Why:* Your VS Code settings file has comments in it, and `ws-host` will not edit a file it cannot read safely.

*Fix:* It listed the settings it wanted to add. Open your settings (`Ctrl+Shift+P`, *Preferences: Open User Settings (JSON)*) and add them
by hand, or remove the comments and run it again.

=== A repository was "left alone"

*Why:* You have changes you have not committed, or your commits and the shared ones have both moved on. This is not an error; it protects
your work.

*Fix:* Commit or push your changes, then run `ws-host workspace ensure` again. `ws-host help recover` explains each case.

=== The prompt shows strange boxes instead of icons

*Why:* The default prompt, `ws-host-pretty`, draws icons from a Nerd Font, and Windows Terminal is using a font that does not have them.

*Fix:* Either install a Nerd Font and choose it, or use the plain prompt.

* *Install a font (once, on Windows):* download https://www.nerdfonts.com/font-downloads[CaskaydiaCove Nerd Font], unzip it, select the font files,
  right-click and choose *Install for all users*. Then in Windows Terminal open *Settings*, *Profiles*, *Debian*, *Appearance* and set *Font face* to
  `CaskaydiaCove Nerd Font`. Close the window and open Debian again. Microsoft explains where:
  https://learn.microsoft.com/en-us/windows/terminal/customize-settings/profile-appearance#font-face[font face].
* *Or use the plain prompt:* run `ws-host shell add bash --plain`, and put `WS_HOST_PROMPT=plain` in `~/.config/workspaces-host/ws-host.env`
  so setup keeps it that way.
