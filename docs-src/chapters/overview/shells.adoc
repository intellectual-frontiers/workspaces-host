[#shells]
== Shells: bash is supported, fish is best

`bash` and `oh-my-posh` are fully supported. Your login shell stays `bash`, `oh-my-posh` draws your prompt in it, and
nothing in `ws-host` depends on which shell you use.

`fish` 4 is the best experience, and I recommend it. It suggests and colors as you type without any plugin, and
`oh-my-posh` looks and behaves best in it. The `shell` kit, installed by default, installs `fish` 4 and `oh-my-posh` together with the
prompt themes, `themes/ws-host-pretty.omp.json` and `themes/ws-host-plain.omp.json`:

----
ws-host kit add shell
----

On Debian 13 the kit uses the distribution's `fish` 4.0. Ubuntu 24.04 ships `fish` 3.7, so the kit fetches the fish
project's own 4.x package, checks its fingerprint and unpacks it under `~/.local/share/workspaces-host/tools`; nothing in
your system directories changes beyond the packages the kit names.

Try it without changing anything by typing `fish`. Making it your login shell is one separate step that only you take, and
`ws-host` never takes it for you:

----
command -v fish | sudo tee -a /etc/shells
chsh -s $(command -v fish)
----

== The prompt, in either shell

The prompt is part of the first impression, so you do not have to ask for it. Setup installs `oh-my-posh` and a theme (the `shell` kit is
installed by default, with `base`) and gives `bash`, and `fish` when it is there, the same prompt: your folder, what git is doing, how
long the last command took and whether it worked.

It adds a few lines between marker comments to `~/.bashrc` or to fish's `config.fish`, after keeping a copy of the file in
`~/.local/state/workspaces-host/backups`. A second run changes nothing. To see it in the window you are in, type `exec bash -l`.

=== Tab completion

Type `ws-host`, a space, and press `Tab`: the shell lists every command, finishes the one you start, offers its options when you type `--` and
fills in the things it works on, such as your repositories and kits. It works in bash and in fish.

Setup puts one file where each shell already looks for completions (`~/.local/share/bash-completion/completions/ws-host` for bash, and
`~/.config/fish/completions/ws-host.fish` for fish), so no startup file is touched. The file is made from the same list of commands that
`ws-host command list` shows, so it never falls behind, and setup renews it each time it runs. bash needs the `bash-completion` package, which
the `base` kit installs. To redo it by hand: `ws-host completion add bash` or `ws-host completion add fish`. It starts in a new terminal window.
A completion file of your own with that name is never overwritten.

=== Two themes: pretty and plain

[cols="1,3"]
|===
| `ws-host-pretty` | The default. It draws icons from a Nerd Font, so it needs one installed on Windows and chosen in your terminal (below).
| `ws-host-plain` | The same layout made only of emoji and box lines. It looks right in Windows Terminal's own font, with nothing to install.
|===

Both live in the `themes` folder of your `workspaces-host` copy.

=== Install a Nerd Font on Windows (for the pretty theme)

You do this once, in Windows and not in Debian:

. Download a font from https://www.nerdfonts.com/font-downloads[nerdfonts.com], for example *CaskaydiaCove Nerd Font*, which looks like
  Windows Terminal's own, or *Meslo*. Unzip the file.
. Select the font files in the folder, right-click, and choose *Install for all users*.
. In Windows Terminal open *Settings*, *Profiles*, *Debian*, *Appearance*, and set *Font face* to `CaskaydiaCove Nerd Font` (or the
  one you installed). Microsoft explains where:
  https://learn.microsoft.com/en-us/windows/terminal/customize-settings/profile-appearance#font-face[font face].

`ws-host vscode ensure` already sets VS Code's terminal to look for a Nerd Font, so the prompt looks the same there.

=== Modern tools: `ls`, `cat`, `top`, `cd` and `git diff`

The `base` kit installs a set of modern command-line tools, and the `modern-cli` kit makes your shells use them. Setup applies it for you when the tools are
there; you can also run `ws-host kit add modern-cli` at any time. In bash and fish (the same lines, written for each) you get:

[cols="1,3"]
|===
|`ls`, `ll`, `la`, `lt`, `tree` |https://github.com/eza-community/eza[eza], with git status and icons; `ll` and `la` are the long forms, `lt` a two-level tree
|`cat` |https://github.com/sharkdp/bat[bat] in plain form, with no pager, so it reads like cat but with colors; pipes still get the raw text
|`top` |https://github.com/aristocratos/btop[btop]
|`z`, `zi` |https://github.com/ajeetdsouza/zoxide[zoxide]: `z docs` jumps to the folder you use most that matches
|Ctrl+R, Ctrl+T, Alt+C |https://github.com/junegunn/fzf[fzf] search for history, files and folders
|`..`, `...` |go up one or two folders
|`git diff`, `git log -p` |https://github.com/dandavison/delta[delta] as git's pager, with line numbers and `n`/`N` to move between files
|===

`grep`, `find`, `sed`, `ps`, `du` and `df` are left alone on purpose: scripts and muscle memory depend on them. `\ls` or `command ls` gives you the old `ls` when you want it.
The git lines go first in `~/.gitconfig`, so anything you set yourself below them wins.

*The icons need a Nerd Font*, the same one the pretty prompt uses (see above). Without one `eza` shows boxes where icons go. To leave the icons out, put
`WS_HOST_PROMPT=plain` in `~/.config/workspaces-host/ws-host.env`. To keep your old commands, put `WS_HOST_MODERN=no` in the same file and delete the lines between the
`>>> workspaces-host: modern-cli` markers.

=== Change the theme

* *Use the plain theme now:* `ws-host shell add bash --plain` (and `fish`). `ws-host shell add bash` goes back to the pretty one.
* *Keep it plain whenever setup runs:* put `WS_HOST_PROMPT=plain` in `~/.config/workspaces-host/ws-host.env`.
* *Keep your own prompt:* put `WS_HOST_PROMPT=no` in the same file, and delete the lines between the markers in `~/.bashrc`.
* *Edit a theme:* copy `themes/ws-host-pretty.omp.json` to a file of your own, change it (the settings are explained at
  https://ohmyposh.dev/docs/configuration/overview[ohmyposh.dev]), and put the path of your file in the marked lines in place of the theme path. Asking an AI to
  change it for you works well, and setup never puts the standard lines back over lines you edited; only `ws-host shell add` does.
* *Take the lines out:* delete the lines between the markers, which say `>>> workspaces-host` and `<<< workspaces-host`.

The one rule I keep for shells is that `ws-host` never edits your login shell, your git configuration or your VS Code settings
unasked. The prompt lines and the modern-tools lines are the only things setup adds to your shell files and `~/.gitconfig`, they are marked, they are backed up, and one setting turns
each off. It tells you what it recommends and offers a button; you press it or you do not.
