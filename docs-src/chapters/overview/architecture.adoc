== How it is built

----
ws-host                  a POSIX sh launcher: fetches mise, Python and uv into its own store on first run, finds the clone through any symlink
install.sh               checks git, curl and xz, clones, links ws-host, prepares the runtime, runs doctor
ws_host/
  core/                  standard library only: registry, resources, renderings, errors,
                         typed arguments, the env-file parser, logging
  commands/              one module per noun: workspace repo auth kit vscode docs skill
                         doctor check test context help command fresh
  kits/                  base press rust shell
  help/                  the topics: start repos signin trust kits shell editor ai extend recover
  install/               the two installers: apt.py and fetch.py
  lib/                   code behind the commands: git, repositories, trust, kit planning
docs-src/                this book; Part II is generated
tests/                   standard-library unittest with real temporary git repositories
----

The launcher runs the plain standard-library interpreter that ws-host's own mise installed, so no host Python or site-packages are ever involved. The
registry imports every module under the commands, kits and help packages and records what they declare. The core never
imports a package. Every command returns one `Resource`, and the same resource becomes text, JSON or HTML.

=== Two installers

`apt` installs what your distribution ships, through `sudo`, and says so before it asks for your password. A package the
distribution lacks is reported and skipped, and the kit's checks say whether that matters. `fetch` downloads a file,
verifies its SHA-256 against the one in the kit's code before anything is unpacked, unpacks it into
`~/.local/share/workspaces-host/tools/<name>/<version>`, repoints a `current` link atomically, and links the binaries into
`~/.local/bin`. A wrong fingerprint installs nothing. There is no third installer.

=== Safe updating

`repo sync` runs `git fetch` and then `git merge --ff-only`. It never pulls, rebases, merges any other way, or stashes. A
repository with uncommitted tracked changes, diverged commits, no upstream, no branch, or an operation in progress is left
exactly as it was and reported in plain words. Each rule is a test: a reattach that rebased someone's unpushed work, or a failed clone reported as done, would fail it.

=== The wire shape

Every orchestrator answers `command list`, `command show` and its resources in one shape, so the editor needs no
knowledge of any of them. A document names its schema as `<name>/<kind>@<n>`; the Workspaces Console reads versions up to the one it
knows and says "update needed" in plain words about a newer one.

=== How the editor draws `ws-host`

`ws-host` also says how it should look, so the editor holds nothing about it. `ws-host command list` returns, with the commands, a title
and an icon for each (the title is what you see in the command palette, such as *Install Kit…*, with the three dots when it asks you for
something first) and a `presentation` block with its views and nouns. The views are *Workspace* (your repositories), *Kits* and *Setup*, and
the rows of the repository and kit lists carry a status the editor turns into a colored icon. The declarations are in
`ws_host/commands/presentation.py`, and `ws-host check registry` fails when a title, an icon or a view is not well formed.

A repository tells the editor where its command line is in `.workspaces-host/provider.toml`, which names its launcher. This repository's says
`launcher = "./ws-host"`, so the editor finds `ws-host` here like any other provider.
