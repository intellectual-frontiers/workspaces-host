[#onedrive]
== OneDrive: sign in, look, copy

`ws-host` can list, copy up and copy down files in a Microsoft OneDrive, for a home or a work account, so that you can share a file with a reviewer and have them comment on it there. It needs
no app registration, no administrator and no setting. This chapter says how to set it up, what each command does, and what it never does.

=== Set up

----
ws-host kit add microsoft
ws-host auth new microsoft --host work
----

The first command installs Microsoft's own sign-in library. The second opens a Microsoft page in your browser (the Windows browser, if you use WSL), where you sign in with your password and any
second factor your account asks for. ws-host never sees them; it receives only the finished sign-in. It prints the page's address as well, in case the browser does not open. Give each account a name with `--host`,
for example `work` and `home`, and name one with `--account` when you have both. `ws-host auth status` lists them beside GitHub.

The sign-in lasts for as long as Microsoft's tokens do, which is normally about three months of not using it, and your organization may set it shorter. When it ends, a command says so and offers the
same sign-in again. It is kept in your system keyring when there is one. Most WSL setups have none, so it is kept in a file only you can read, under `~/.IdentityService`, and ws-host says so.

If Microsoft shows a page that says *You don't have access to this* after you pick your account, your organization may allow only one way of signing in. Try the other:

----
ws-host auth new microsoft --host work --method code
----

That shows a short code and an address; you type the code on that page. Use `--method code` from the start on a machine with no browser (a server, an SSH session). If neither works, ask your administrator
to read the Entra sign-in log for the time of the attempt: it names the Conditional Access policy that blocked it. If you have an app registration of your own, `--own-app` signs in with it, and asks for
its two IDs the first time, checks them and keeps them for that account.

=== Look

----
ws-host onedrive list
ws-host onedrive list Documents
ws-host onedrive show Documents/report.pdf
----

Paths start at the top of your OneDrive. `list` shows the folders first, then the files with their sizes. Neither command changes anything.

=== Copy up

----
ws-host onedrive add ~/files/report.pdf Documents/report.pdf --dry-run
ws-host onedrive add ~/files/report.pdf Documents/report.pdf
ws-host onedrive add ~/files/reports Archive/reports --update
----

`add LOCAL REMOTE` copies a file, or a whole folder with its folders, into OneDrive. Folders that are missing are made on the way. Without an option a file that is already there is left alone and
said so. The options:

[cols="1,3"]
|===
|`--dry-run` |sends nothing, and says what would be copied; it also checks every name, so it finds a problem before a real copy would
|`--update` |copies the files that are new and the ones whose content changed, and sends nothing that has not changed. OneDrive keeps each earlier copy as a version, so nothing is lost and reviewers' comments stay
|`--replace` |copies every file, replacing the ones already there (OneDrive still keeps the earlier copies as versions)
|`--include PATTERN` |copies only names that match, such as `'*.pdf'`; repeat it for more
|`--exclude PATTERN` |leaves out names that match any part of the path, such as `'.*'` for hidden files; repeat it for more
|`--skip-copies` |leaves a file out when the folder already holds one with the same content under another name, so a file that is renamed by its date does not go up twice
|`--also LOCAL=REMOTE` |copies another file or folder in the same run; many copies in one run sign in once, which is much faster than one run each
|`--account NAME` |which sign-in to use, when you have more than one
|===

Whether a file has changed is decided by the checksum OneDrive states for the copy it holds (SHA-1, or QuickXorHash for work accounts), and by size and date when it states none. After each copy ws-host checks
the checksum OneDrive states for what it received, and says so, never hides it, if it differs. A file over 4 MiB goes up in pieces.

OneDrive does not allow `"`, `*`, `:`, `<`, `>`, `?` or `|` in a name, nor a name that ends in a space or a dot. ws-host checks every name first and stops before sending anything, saying which name
and why. The programs that call it, such as a repository's own command line, make names OneDrive can hold.

=== Copy down

----
ws-host onedrive sync Documents/reports ~/files/reports --dry-run
ws-host onedrive sync Documents/reports ~/files/reports
----

`sync REMOTE LOCAL` copies a file or a folder from OneDrive to this machine. A local file that has the same size is left alone, and one that differs is kept unless you add `--replace`.

=== What it never does

It never deletes anything in OneDrive or on your machine. It never replaces a file without `--update` or `--replace`. It sends the sign-in only to Microsoft's own address, never to a download or upload link.
It never starts a text-mode browser in your terminal, and it opens a sign-in address only if it is a plain `https` one.

=== A synced folder

OneDrive's own sync program exists only for Windows and macOS. On WSL, let the Windows program sync, mark the folders you need as *Always keep on this device*, and read them at
`/mnt/c/Users/<you>/OneDrive`.
