[#sign-in]
== Sign in to GitHub

There is one way to sign in, and it is the only way I support. It uses a short code and your web browser. You never type a password into
the Debian window, and you never create a token or an SSH key.


.How signing in works
image::figures/fig-g3.png[Four steps: ask for a code, read it, type it in your browser, run setup again,width=90%]

=== Step 1: Ask for a code

In the Debian window, type:

----
ws-host auth new github
----

It prints a line like this:

----
To sign in, open https://github.com/login/device and type this code: ABCD-1234
----

=== Step 2: Type the code in your browser

. Hold Ctrl and click the address, or copy it and paste it into your normal web browser on Windows.
. If GitHub asks you to sign in, do that as you normally do.
. Type the code from the Debian window. Press *Continue*, then *Authorize*.
. Go back to the Debian window. It says `You are signed in to github.com`.

The code works for a few minutes. If it expires, run the command again for a new one. GitHub's own page explains the same login:
https://cli.github.com/manual/gh_auth_login[gh auth login].

=== Step 3: Run the setup again

----
ws-host workspace ensure
----

This time it goes on. It copies your repositories into `workspaces`, brings them up to date, installs the tools they ask for, and checks
your machine. It is safe to run as often as you like: if you have changes of your own in a repository, it leaves that repository
exactly as it was and tells you your work is safe.

If it says it could not copy a repository and mentions `Username`, you are not signed in yet or you cannot see that repository. See
<<troubleshooting>>.

TIP: In VS Code the same sign-in is a notification with a button, *Copy code and open browser*, or the command *Workspaces Console: Sign In…*. It runs `ws-host auth new github` for you. You will meet it in the next chapter.

=== Whose commits they are

Git puts a name and an email on every commit. When you sign in to GitHub, `ws-host` sets them for you if git has none: your GitHub name, and GitHub's private "noreply" address for you
(`<number>+<login>@users.noreply.github.com`), which links the commits to your account and is never refused for showing a private email. It tells you in one sentence whose commits they will be.
It never changes a name or email you set yourself, and it never fails your sign-in. `ws-host workspace set --git-identity` does it again, `--git-name "Your Name"` and `--git-email you@example.com`
set them yourself, and `ws-host doctor` says when they are missing.

If you want your work address on the commits you make in your organization's repositories, and only there, run `ws-host workspace set --work-email you@company.example` (`none` takes it away). It
applies to the folders of the organizations you trust, and everywhere else the noreply address stays. After you sign in to Microsoft, ws-host shows the work address of that account for you to copy.

=== Microsoft OneDrive (optional)

If you also work with files in Microsoft OneDrive, `ws-host auth new microsoft --host work` signs you in the same way, with a page in your browser and no password in the terminal. <<onedrive>> has everything about it.
