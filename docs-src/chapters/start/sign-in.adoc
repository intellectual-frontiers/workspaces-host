[#sign-in]
== Sign in to GitHub

There is one way to sign in, and it is the only way I support. It uses a short code and your web browser. You never type a password into
the Debian window, and you never create a token or an SSH key.


.How signing in works
image::figures/fig-g3.png[Four steps: ask for a code, read it, type it in your browser, run setup again,width=90%]

=== Step 1: Ask for a code

In the Debian window, type:

----
ws-host auth new github
----

It prints a line like this:

----
To sign in, open https://github.com/login/device and type this code: ABCD-1234
----

=== Step 2: Type the code in your browser

. Hold Ctrl and click the address, or copy it and paste it into your normal web browser on Windows.
. If GitHub asks you to sign in, do that as you normally do.
. Type the code from the Debian window. Press *Continue*, then *Authorize*.
. Go back to the Debian window. It says `You are signed in to github.com`.

The code works for a few minutes. If it expires, run the command again for a new one. GitHub's own page explains the same login:
https://cli.github.com/manual/gh_auth_login[gh auth login].

=== Step 3: Run the setup again

----
ws-host workspace ensure
----

This time it goes on. It copies your repositories into `workspaces`, brings them up to date, installs the tools they ask for, and checks
your machine. It is safe to run as often as you like: if you have changes of your own in a repository, it leaves that repository
exactly as it was and tells you your work is safe.

If it says it could not copy a repository and mentions `Username`, you are not signed in yet or you cannot see that repository. See
<<troubleshooting>>.

TIP: In VS Code the same sign-in is a notification with a button, *Copy code and open browser*, or the command *Workspaces Console: Sign In…*. It runs `ws-host auth new github` for you. You will meet it in the next chapter.

=== Microsoft OneDrive (optional)

Install the `microsoft` kit, then sign in the same way, with a code and a web page and no password in the terminal:

----
ws-host kit add microsoft
ws-host auth new microsoft --host work
ws-host onedrive list
----

Give each account its own name with `--host`, for example `work` and `personal`, and name one with `--account` when you have both. `ws-host onedrive sync REMOTE LOCAL`
copies a file or folder to this machine, and `ws-host onedrive add LOCAL REMOTE` copies one into OneDrive. A file that is already at the other end is left alone, and
ws-host says so, unless you add `--replace`; `--dry-run` shows what would be copied.

Many work organizations need an administrator to approve the app that signs you in. If the sign-in stops for that reason, register an app of your own once, in the Microsoft Entra admin center:

. Choose *App registrations*, then *New registration*, and accept *accounts in any organizational directory and personal Microsoft accounts*.
. Under *Authentication*, add the platform *Mobile and desktop applications* with the redirect `https://login.microsoftonline.com/common/oauth2/nativeclient`, and turn on *Allow public client flows*.
. Under *API permissions*, add the delegated Microsoft Graph permissions `Files.ReadWrite.All` and `User.Read`, and grant consent if your organization asks for it.
. Put the *Application (client) ID* in `WS_HOST_MICROSOFT_CLIENT_ID` in `~/.config/workspaces-host/ws-host.env`.

If you made the app for your organization only, also put its *Directory (tenant) ID* in `WS_HOST_MICROSOFT_TENANT`. If, after you pick your account, Microsoft shows a page that says *You don't have access to this*, it is this
approval that is missing; nothing is wrong with your account. An administrator can also grant consent for the app under *Enterprise applications*, then *Permissions*, then *Grant admin consent*.

The sign-in is kept in your system keyring when there is one. Most WSL setups have none, so it is kept in a file only you can read, under `~/.IdentityService`, and ws-host tells you so.
OneDrive's own sync program exists only for Windows and macOS: on WSL, let the Windows program sync, mark the folders you need as *Always keep on this device*, and read them at
`/mnt/c/Users/<you>/OneDrive`.
