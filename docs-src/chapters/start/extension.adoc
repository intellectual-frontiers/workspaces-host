== How the Workspaces Console works

[TIP]
====
The Console is the friendly way in, not the only way. It adds nothing that `ws-host` cannot do on its own: every button runs a `ws-host` command, and the command line is the complete program. If you ever prefer to type, work over SSH or with an AI, or write a script, you lose nothing.
====

`ws-host` ships one editor extension, the Workspaces Console. It is VS Code's window onto `ws-host`, and onto every other repository's command line. It is built
in the `workspaces-host` repository and released together with `ws-host`. It is not on the VS Code Marketplace, and that is on purpose: `ws-host vscode
ensure` downloads the package from the latest release, checks its SHA-256 fingerprint against the one GitHub reports for it, and installs it with VS Code's
own `code` command, the same thing as VS Code's
https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#_install-from-a-vsix[install from a VSIX] feature. There is no account, and no network
connection from the extension itself.

`ws-host vscode ensure` installs a release once, and only a package whose fingerprint it can verify. When there is no such release, or the file does not match its
fingerprint, it says so and installs nothing. Nothing is built on your computer, and no code from a repository you have not trusted runs.

`ws-host vscode ensure` also writes `workspaces.code-workspace` in your workspaces folder. It lists the repositories you work in, and opening it
(File, Open Workspace from File) shows each repository's own commands side by side. The Workspaces Console finds a repository's command line by the file
`.workspaces-host/provider.toml`; `ws-host` has one.

=== What you see

.Every button is a command you could type
image::figures/fig-g4.png[Four buttons beside the ws-host line each one runs,width=90%]


* The *Home* view says what needs you. Each row says what is wrong in plain words, shows the exact line that fixes it, and has a *Run* button where
  a command can do it for you and a *Copy* button. Where no command can, it says what you do yourself. The count is on the status bar, and a click
  on the status bar opens Home.
* The views `ws-host` asks for, *Workspace* (your repositories), *Kits* and *Setup*, with a colored icon for how each row stands.
* Every result opens in one panel, with buttons for what you can do next. A command that writes shows you what it would change first.
* *Workspaces Console: Learn a Topic…* lists the same pages as `ws-host help`, and each step is a button.
* *Workspaces Console: Get Help…* and *Copy Context…* gather a report with no passwords in it. Paste it to a person or an AI.
* Problems from the checks appear in VS Code's *Problems* panel, at the file and line.

=== What it will not do for you

It will never decide for you. Trusting a repository asks you in a dialog, and nothing in VS Code, including an AI assistant, can press that
button for you. It runs nothing in Restricted Mode and nothing from a repository you have not trusted, it collects nothing, and it opens no
network connection. The Workspaces Console's own guide is in the `console/` folder of the `workspaces-host` repository.

=== Why trust matters

Copying a repository does not let its code run. You trust a repository on purpose, once, and you can stop trusting it any time.
`ws-host help trust` explains it, and so does Learn.

VS Code asks *Do you trust the authors of the files in this folder?* Press *Yes, I trust the authors*. If it says it is in *Restricted
Mode*, that is the same question; press *Manage*, then *Trust*. See https://code.visualstudio.com/docs/editor/workspace-trust[Workspace Trust].
