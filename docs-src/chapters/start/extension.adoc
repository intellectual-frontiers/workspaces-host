== How the IF Console works

`ws-host` ships no editor extension of its own. VS Code's window onto `ws-host`, and onto every other repository's command line, is the
IF Console, one extension that the public root (`.github`) builds. It is not on the VS Code Marketplace, and that is on purpose: `ws-host vscode
ensure` builds it on your computer from the public root's own code and installs the package it makes with VS Code's own `code` command, the same
thing as VS Code's
https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#_install-from-a-vsix[install from a VSIX] feature. There is nothing to
download, no account, and no network connection from the extension itself.

If the public root has published a release with the IF Console's package and its SHA-256 fingerprint, `ws-host` downloads that package, checks the
fingerprint, and installs it. That needs no build and no trust. Otherwise it builds the package, and building runs code that lives in the public
root, so `ws-host` asks you once to trust that repository, with a typed `yes`. It builds again only when the public root has changed, which is
when you run `ws-host update` or `ws-host workspace ensure` and then `ws-host vscode ensure`.

`ws-host vscode ensure` also writes `workspaces.code-workspace` in your workspaces folder. It lists the repositories you work in, and opening it
(File, Open Workspace from File) shows each repository's own commands side by side. The IF Console finds a repository's command line by a file at
its root, `.if-console.env`; `ws-host` has one.

=== What you see

* The *Home* view says what needs you. Each row says what is wrong in plain words, shows the exact line that fixes it, and has a *Run* button where
  a command can do it for you and a *Copy* button. Where no command can, it says what you do yourself. The count is on the status bar, and a click
  on the status bar opens Home.
* The views `ws-host` asks for, *Workspace* (your repositories), *Kits* and *Setup*, with a colored icon for how each row stands.
* Every result opens in one panel, with buttons for what you can do next. A command that writes shows you what it would change first.
* *IF Console: Learn a Topic…* lists the same pages as `ws-host help`, and each step is a button.
* *IF Console: Get Help…* and *Copy Context…* gather a report with no passwords in it. Paste it to a person or an AI.
* Problems from the checks appear in VS Code's *Problems* panel, at the file and line.

=== What it will not do for you

It will never decide for you. Trusting a repository asks you in a dialog, and nothing in VS Code, including an AI assistant, can press that
button for you. It runs nothing in Restricted Mode and nothing from a repository you have not trusted, it collects nothing, and it opens no
network connection. The IF Console's own guide is in the public root, in `tools/if-console`.

=== Why trust matters

Copying a repository does not let its code run. You trust a repository on purpose, once, and you can stop trusting it any time.
`ws-host help trust` explains it, and so does Learn.

VS Code asks *Do you trust the authors of the files in this folder?* Press *Yes, I trust the authors*. If it says it is in *Restricted
Mode*, that is the same question; press *Manage*, then *Trust*. See https://code.visualstudio.com/docs/editor/workspace-trust[Workspace Trust].
