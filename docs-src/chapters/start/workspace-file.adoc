[#workspace-file]
== One window for all your repositories

You work in more than one repository, and VS Code can show them together in one window. It does this with a *workspace file*, a small file named
`workspaces.code-workspace`. This page says what I suggest, and you stay free to do it your own way.

=== The default

Start from `~/workspaces/workspaces.code-workspace`. `ws-host vscode ensure` writes it and keeps its list of repositories current, so it
holds every repository you have copied and you do not edit it by hand. Starting there puts all your repositories in one window, which is the easiest
way to begin. A window opened on one repository hides the others and the Workspaces Console cannot show them all.

=== Make your own

The default is a starting point, not a limit. Make another file next to it when one list is too long or mixes things that do not belong together.
Two common reasons:

* *Several Git services.* Work from GitHub, GitLab and others? Make `github.code-workspace` and `gitlab.code-workspace`, each listing that service's repositories.
* *Several organizations on one service.* On GitHub across more than one organization? Make one file per organization, such as
  `intellectual-frontiers.code-workspace`, so each window holds one organization's repositories.

To make one, copy `workspaces.code-workspace` to a new name in `~/workspaces`, then delete the folders you do not want in that file. Paths are
relative to `~/workspaces`, so a copied file works as it is. Open it with `code ~/workspaces/<name>.code-workspace`. `ws-host vscode ensure` only
manages the default file and never touches yours.

=== Open it

In the Debian window:

----
code ~/workspaces/workspaces.code-workspace
----

Or in VS Code: *File*, *Open Workspace from File*, and choose the file. VS Code remembers it. Next time, *File*, *Open Recent* lists it first, and
VS Code reopens it when it starts. Its title bar begins with *Workspaces*, so you can tell it from a window that has only one repository.

You know it worked when the *Explorer* on the left lists every repository by its short name, each one a folder you can open.
Microsoft's page on this is https://code.visualstudio.com/docs/editing/workspaces/multi-root-workspaces[Multi-root workspaces].

=== Add a repository

----
ws-host repo add github.com/acme/tools
ws-host vscode ensure
----

The repository appears in the Explorer after `ws-host vscode ensure`. Reload the window if it does not: `Ctrl+Shift+P`, `Reload Window`.

=== Where the files live

Workspace files go in your workspaces folder, `~/workspaces`, and nothing else belongs next to them. Every repository in a file is listed relative to that
folder, for example `github.com/acme/tools`, never by a full path. That is why the file keeps working if the folder is moved or renamed,
and why you can read it: it lists the same folders you see in `~/workspaces`.

=== What is in the file

A list of your repositories with short names, a window title that starts with *Workspaces*, and a recommendation to use the Workspaces Console. `ws-host
vscode ensure` adds what is missing. It never changes a line you wrote yourself, and it leaves the file alone if it has comments it cannot safely rewrite.

=== When it looks wrong

* *The Explorer shows only one repository.* You opened a folder, not the file. Close the window and open the file as above.
* *A repository is missing.* Run `ws-host vscode ensure`.
* *VS Code asks whether you trust the authors.* Press *Yes, I trust the authors* for repositories you chose to copy; see <<vscode>>.
