# Spike: chezmoi for ws-host's managed configuration

Run on 2026-10-05 with chezmoi 2.73.0 (installed through mise, 40 MB), on Ubuntu 24.04 and Debian 12.15. Re-run with
`./run.sh <chezmoi binary> [WORK]` (under a second; every test uses a throwaway home). A spike, not a spec.

## Verdict

chezmoi can carry everything ws-host writes into a person's home, with the properties ws-host already promises: nothing outside a
marked block is touched, what a person set is kept, a second run changes nothing, and what a person edited is not overwritten. It
needs a small wrapper for two gaps (it overwrites a file it never wrote, and it keeps no backups). Recommended, as approved, with
those two behaviors written into the wrapper and tested.

## What was ported

| ws-host today | chezmoi source (`home/`, `workspace-home/`) | Result |
|---|---|---|
| `shell add bash`: marked block in `~/.bashrc` (`shell.py`, 148 lines) | `modify_dot_bashrc` (a modify template, 23 lines) | Pass |
| `shell add fish`: marked block in `config.fish` | `dot_config/fish/conf.d/ws-host.fish.tmpl`, one whole file (the `conf.d` model; no edit of `config.fish`) | Pass |
| completions for bash and fish (`lib/completion.py`) | generated files committed in the source (`dot_local/share/bash-completion/...`, `dot_config/fish/completions/ws-host.fish`), regenerated by ws-host's own generator | Pass |
| prompt themes | plain files under `dot_local/share/workspaces-host/themes/` | Pass |
| VS Code baseline settings (`merge_settings`) | `.chezmoitemplates/vscode-settings`, included by a `modify_settings.json` for `~/.config/Code/User` and for `~/.vscode-server/data/Machine` | Pass |
| the workspace file (`workspace_step`) | `workspace-home/modify_workspaces.code-workspace`, a second source applied to the person's workspaces folder | Pass |
| WSL or not | ws-host puts `wsl` in the data; `.chezmoiignore` selects which settings path applies | Pass |

## What passed

1. First apply into a home that already has a `.bashrc` and `settings.json`: the person's lines come first and are untouched; the
   person's `files.autoSave: off` is kept and the missing keys are added; `chezmoi status` and `chezmoi diff` show the change first.
2. A second apply changes nothing: `chezmoi verify` exits 0, `status` is empty, every file byte-identical. This is `doctor`'s drift check.
3. A person edits a file ws-host owns completely: a non-interactive apply refuses (`has changed since chezmoi last wrote it`, exit 1),
   leaves the file as it was, and `status` marks it `MM`. Only `--force` restores it. This is the "never touch your work" rule.
4. A start marker with no end marker: that file is left as it was with a message ws-host can translate, and `--keep-going` applies the rest.
5. Turning the prompt off removes the block and the blank line that came with it, so adding then removing restores the original bytes.
6. A `settings.json` with comments cannot be parsed: the file is left as it was and the error says so (ws-host's current
   "left alone" behavior).
7. A backup of every file about to change, taken from `chezmoi status` before the apply, restores a file exactly (undo works).
8. A person's own chezmoi (default source, config and state) and ws-host's do not see each other. If theirs manages the whole
   `.bashrc`, their apply replaces ws-host's block and ws-host's apply puts it back; `doctor` should say so, since the two will keep
   undoing each other.
9. The source can be read-only package data: applied as an ordinary user from a source with write permission removed.
10. WSL: with `wsl: true`, settings go to `~/.vscode-server/data/Machine/settings.json` and nothing is written under `~/.config/Code`.
11. The workspace file in a relocatable folder: folders the person added and their own `window.title` are kept; a newly cloned
    repository is added; a second apply is a no-op.
12. A file that exists and is not ws-host's is protected (see below); the other files still apply.
13. An apply takes about 50 to 75 ms. Debian 12 passes the whole script.

## What needed care

- **A modify template is a file named `modify_<name>` with no `.tmpl` extension that contains `chezmoi:modify-template`;** the
  existing contents are `.chezmoi.stdin`. Shared text is reached with `includeTemplate`, not `template`.
- **Use `regexReplaceAllLiteral`.** `regexReplaceAll` reads `$PATH` and `$HOME` in the replacement as group references and silently
  empties them. The idempotence check caught this.
- **Always run with `--no-tty` and standard input closed** (`</dev/null`); with a pipe left open, chezmoi waited and the harness hung.
- **chezmoi overwrites a file it never wrote, without asking.** It prompts only when a file it wrote has since changed. So ws-host
  must find files that exist, differ and do not start with a ws-host header, and list them in the data (`protect`), which
  `.chezmoiignore` honors (test 12). With the check, the person's file is kept and the others apply.
- **chezmoi keeps no backups.** The wrapper copies each file `status` reports as modified into ws-host's state directory first (test 7).
- **No JSON output.** `status` is two columns of text and `verify` has an exit code; the wrapper turns them into ws-host's resources.
- **Go templates are less exact than ws-host's Python** for the workspace file: existing folders are matched by their path text
  after trimming `./`, not by a normalized absolute path.
- **chezmoi's messages name chezmoi and its own prompts;** ws-host must translate them into its plain wording.

## Size of the change

The templates and ignore file are 96 lines. The Python they replace is `shell.py` (148 lines), the settings and workspace merging in
`vscode.py` (about 110) and the completion installer (about 30), but a wrapper of roughly 100 lines is added for protection, backup,
status parsing and message translation. The net saving is modest; the gains are a diff before every change, `verify` for `doctor`,
idempotence by construction, and a source that is data a person can read.

## Not tested

Removing the old marker block ws-host already wrote into an existing `config.fish`, and `ws-host shell add` as a command on top of
this; a person on an older chezmoi; running chezmoi under `MISE_SAFE=1` inside a provider's environment (it is ws-host's own
source, not a provider's, so a provider cannot add dotfiles).

## Policy

The default theme is `ws-host-pretty`, assuming a Nerd Font is installed; `ws-host-plain` stays available with `--plain`. A provider
cannot add files to a person's home through this: the source is ws-host's own package data.
